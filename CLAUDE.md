# Проект CodeQuest: Симулятор Космической Корпорации (Техническое задание)

## 1. Общая концепция
CodeQuest — это прогрессивная браузерная игра, симулятор управления космической корпорацией. Развитие идет от основания индивидуального космопорта к сложной инфраструктуре. Механика строится на постепенном расширении: покупка склада, интеграция с верфью, сборка кораблей, наем экипажа и запуск специализированных миссий (добыча, бои). Все системы взаимосвязаны и напрямую влияют друг на друга.

## 2. Архитектура данных (Закладка фундамента)
Разработка ведется с прицелом на масштабирование. Код должен быть разбит на логические ES-модули. Используется объектно-ориентированный подход (ООП).

### Глобальные сущности (Базовые классы)
*   **Космопорт и Игрок (Spaceport / PlayerState):** Хранит стартовый бюджет (кредиты), уровень развития и общую статистику. Является центральным узлом.
*   **Склад (Warehouse):** Управляет инвентарем космопорта. Имеет лимиты вместимости, методы добавления и извлечения компонентов, сырья (руды) и топлива.
*   **Экипаж (CrewMember):** Объекты с параметрами (специализация: пилот/инженер/оператор, уровень навыка, стоимость найма, зарплата за миссию).
*   **Верфь (Shipyard):** Внешняя база данных (каталог). Хранит доступные для покупки модули (двигатели, реакторы, буры, пушки) и включает **Биржу труда** для найма экипажа.
*   **Корабль (Spaceship):** Агрегатор модулей и команды. Рассчитывает итоговые характеристики (масса, доступная энергия, расход топлива) с учетом перков и бонусов экипажа.

## 3. Этапы разработки (Roadmap)
Разработка ведется строгими итерациями. Агенту запрещено переходить к следующему шагу, пока полностью не протестирован и не выведен в UI предыдущий.

*   **Шаг 1: База Космопорта (Ядро) — [ВЫПОЛНЕНО]**
    Созданы ES-модули: `player.js` (класс PlayerState для бюджета), `warehouse.js` (класс Warehouse для инвентаря) и `ui.js` для рендера. Показатели бюджета и склада динамически выводятся на дашборд `index.html`, существующая верстка сохранена.
*   **Шаг 2: Интеграция Верфи и Экипажа — [ВЫПОЛНЕНО]**
    Созданы `shipyard.js` (каталог модулей Верфи) и `crew.js` (Биржа труда). В `index.html` выведены динамические списки для найма и покупки. В `ui.js` реализована механика: покупка проверяет склад и списывает кредиты, найм забирает кандидата с биржи в экипаж Игрока.
*   **Шаг 3: Сборка и Обслуживание (Подготовка к полету)**
    Интеграция купленных модулей со склада в единый объект `Spaceship`. Взаимодействие корабля с космопортом: реализация функции заправки топливом со склада, предстартовая диагностика всех систем (проверка наличия пилота, доступной энергии, лимитов массы).
*   **Шаг 4: Экономика и Добыча (Миссия 1)**
    Введение модулей добычи руды. Написание скрипта первой экспедиции: старт, расчет расхода топлива, работа добывающих модулей, возврат на базу. Реализация Рынка: продажа добытой руды для пополнения стартового бюджета и покупки новых модулей.
*   **Шаг 5: Военная экспансия (Миссия 2)**
    Расширение каталога Верфи боевыми модулями (оружие, щиты). Интеграция боевых характеристик. Написание скрипта военной миссии с базовой механикой получения и нанесения урона.

## 4. Инструкции для агента (Claude Code / Antigravity IDE)
1. **Строгая модульность:** Разделяй логику по отдельным JS-файлам (например, `player.js`, `warehouse.js`, `ship.js`, `crew.js`, `ui.js`). Не создавай монолитный код.
2. **Инкапсуляция:** Используй классы. Данные должны изменяться только через соответствующие методы (геттеры/сеттеры).
3. **Безопасность состояний:** Тщательно валидируй входные данные в функциях (особенно при списании кредитов, проверке лимитов склада, совместимости модулей по энергии и массе).
4. **Синхронизация UI:** При выводе данных на дашборд обновляй DOM точечно, привязывая обновления к изменениям состояния объектов.
5. **Итеративность:** Действуй строго по Roadmap. Не пиши логику для Шага 4, если мы находимся на Шаге 1.

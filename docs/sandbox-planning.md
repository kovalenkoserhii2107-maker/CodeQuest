# Планирование в песочнице

Рабочее пространство находится в начале экрана. Инструкция мира свёрнута; быстрые переходы открывают код, задания, рынки, заявки и API. Рынки можно фильтровать по товару и региону. Блок результата шага показывает изменение баланса и склада, число команд и время исполнения. Проба выводит прогноз, не сохраняя мир. Кнопка отмены останавливает Worker и не применяет его команды. Статус сохранения относится к браузеру, в котором открыта игра.

Кнопка «Настроить раскладку» включает инструменты дашборда; «Готово» возвращает режим чтения. Изменения кода пересчитывают представление после паузы 500 мс; это можно выключить. При ошибке остаётся явно обозначенный последний успешный снимок того же файла. При выборе другого файла старые показатели очищаются. Режим Код/Дашборд/Вместе сохраняется.

## Сравнение вариантов

```js
export function main(cq) {
  const costs = cq.analytics.getUnitCosts();
  const batch = cq.factory.quote("metal", 5);
  cq.print("Затраты на единицу:", costs);
  if (batch.canStart) cq.factory.start("metal", 5);
  else cq.print("Почему нельзя:", batch.reasons);
}
```

factory.quote проверяет сырьё, энергию, мощность, место, технологию и занятость линии без изменений состояния. market.quote возвращает reasons, estimatedUnitCost и estimatedMargin вместе с прежними gross/fee/net/canTrade. Оценка использует самую дешёвую доступную цепочку сырья и энергии, независимо от текущих запасов поставщиков; оборудование, разрешения и доставка (в unitCosts) не включены. Это оценка для решения, а не фактическая себестоимость уже купленных запасов.

## Отложенные продажи

```js
export function main(cq) {
  const orders = cq.market.getOrders();
  if (!orders.some(o => o.status === "pending")) {
    cq.market.placeOrder({
      product: "metal", quantity: 5, buyerId: "foundry",
      minPrice: 19, expiresIn: 24
    });
  }
  cq.print(cq.market.getOrders());
}
```

До восьми активных заявок, история до 48. Цена minPrice — целое 1–1000; expiresIn — 2–120, по умолчанию 24. Заявка не резервирует товары и деньги. Каждый шаг сначала обновляются цены и производство, затем заявки по порядку пробуют выполнить сделку; нехватка ресурсов оставляет pending, причины видны в reasons. На шаге expiresAt заявка уже истекает. Если первая заявка не может исполниться, следующая всё равно проверяется.

Для удалённого покупателя нужен routeId. Исполнение создаёт обычную доставку с закреплённой ценой; деньги придут при её завершении. cancelOrder(id) отменяет только pending; состоявшаяся доставка остаётся в пути. Все изменения шага, включая заявки, откатываются при ошибке скрипта.

Технологии throughput (900 ₽) и logistics (750 ₽) ускоряют новые партии и доставки на один шаг, минимум до одного. Уже запущенные партии и грузы сохраняют прежнее время. warehouse.discard(product, quantity) освобождает место без компенсации; считайте излишки перед списанием.

Задания 12 и 13 вводят оценку партии и отложенные продажи. analytics.getAlerts() даёт подсказки о деньгах, складе, сроках и простое.

## Совместимость и проверка

Сохранения schema=3 мигрируют к schema=4 с пустым списком заявок. Проект, память, партии, доставки, исследования и учебный прогресс сохраняются. Для нового формата повреждённые заявки не исправляются молча.

Проверки: npm test, check-plant.mjs и четыре браузерных сценария в GitHub Actions. Новый сценарий проверяет сохранение модели/undo при повторном выборе файла, отсутствие перерисовки рынка при пробе, результат шага, отмену, фильтры, live-дашборды, независимость графов запуска, заявки и сохранение режима.

В этой сессии интерактивный браузер и просмотр изображений недоступны. Это проверка реализации и поведения по коду и Chromium, без утверждения о полноценном визуальном аудите.

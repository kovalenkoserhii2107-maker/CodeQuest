# Проверка концепции «Городского комбината»

Главная цель — практика JavaScript через управление экономикой и производством. Мир служит источником данных, ограничений и последствий решений. Рост предприятия должен требовать более качественного кода, а не только накопления денег.

## Текущее соответствие

| Ступень | Задача мира | Что практикует игрок |
| --- | --- | --- |
| Задания 1–3 | Прочитать баланс, купить сырьё, запустить партию | Объекты, вызовы функций, параметры, условия |
| Задания 4–6 | Дождаться продукции, выбрать покупателя, повторять действия | Массивы, поиск, циклы по шагам, сохраняемое состояние |
| Задания 7–10 | Контракты, технологии, доставка, несколько линий | Проверки ограничений, сроки, планирование зависимостей |
| Задания 11–13 | Модули, оценка затрат, отложенные продажи | Декомпозиция, расчёт альтернатив, события |
| Практика с тестами | План закупки, выбор линии, отчёт | Чистые функции, граничные случаи, неизменность входа, контракт данных |
| Свободные проекты | Автоматизация, сравнение стратегий, наблюдаемость | Проектирование, отладка, тестирование, собственные интерфейсы |

Механики доступны с начала игры; задания — рекомендуемый маршрут. Это сохраняет свободу экспериментов. Три практики имеют отдельные файлы и проверяются на фиксированных данных без изменения мира. Их функции можно импортировать в настоящие main и render. Проверки не подставляют готовое решение и не требуют конкретного алгоритма, кроме явно описанного результата.

## Целостность мира

Сеттинг — городская мастерская, порт и северные промышленные районы. Сырьё превращается в товары, оборудование ограничивает размер партии, производство занимает игровые шаги. Контракты имеют сроки; доставка резервирует маршрут и фиксирует цену продажи. Местная продажа, отложенная заявка и доставка дают разные условия планирования.

main выполняет последовательные команды на временной копии мира. Только успешный результат и проверенные команды применяются к сохранению, затем проходит один игровой шаг. Ошибка, отмена и пробный запуск не меняют мир и память. Вывод консоли намеренно остаётся: он нужен для отладки неудачного эксперимента.

render читает снимок мира. Его вызов не запускает main, не продвигает время и не сохраняет изменения cq.memory. Снимок дашборда помечен номером шага; при ошибке может оставаться последний успешный снимок с явным сообщением.

## Что исправлено после проверки

- Потеря console.log до исключения и отсутствие вывода из render: сообщения поступают во время исполнения в общую отдельную консоль с источником, шагом, уровнями и фильтрами. Окно можно вынести поверх других вкладок. Ошибка со ссылкой city/path.js:line:column открывает файл и строку.
- Сброс undo и позиции при переключении файлов: модели Monaco и состояния представления сохраняются в рамках сеанса кампании. Закрытие вкладки не удаляет файл; удалённые модели освобождаются. Перезагрузка страницы восстанавливает текст, но не историю undo.
- Потеря недописанного фильтра дашборда при обновлении: значение активного поля, выделение и фокус восстанавливаются для того же дашборда.
- Разрыв между учебными вызовами API и самостоятельной разработкой: добавлены практики с тестами и проекты с критериями проверки.

## Дашборды как часть практики

Конструктор создаёт обычный JS-файл. Его можно читать, редактировать, разбивать на модули и импортировать расчётные функции. Готовые источники и примеры помогают начать, дальнейшие решения остаются в коде. Виджеты: показатели, текст, таблицы, линейные графики, области, столбцы, индикаторы загрузки; фильтры передаются через view.inputs. Раскладка, порядок, ширина и скрытие виджетов сохраняются отдельно от кода.

Графики используют фактическую историю мира (до 120 шагов); оценочная себестоимость и маржа должны быть подписаны как оценочные. Выручка не равна прибыли, а изменение баланса включает закупки, энергию, исследования и оборудование. HTML/CSS доступны в отдельном iframe без исполнения вложенных скриптов: расчёты выполняются в render.

## Честные границы

Первые 13 заданий подтверждают действия в игре, но не доказывают качество алгоритма: часть условий учитывает накопленные показатели. Поэтому рядом доступны проверки чистых функций и свободные проекты без искусственной отметки «профессия освоена». Для полноценного курса ещё нужны более глубокие темы: обработка ошибок, собственные наборы тестов, алгоритмы планирования, асинхронные источники данных.

Экономика ограниченная и детерминированная, без мультиплеера и настоящего внешнего рынка. Нет постоянно работающих процессов как в Bitburner: каждый main и render исполняется в новом Worker с лимитом 3 секунды; долговременное состояние хранится в cq.memory. Асинхронные функции допустимы, но setTimeout не ускоряет игровое производство.

Не стоит расширять мир новыми кнопками, которые заменяют код. Следующая полезная ступень — задачи, в которых игрок строит диспетчер, проверяет крайние случаи и объясняет результат по данным.
